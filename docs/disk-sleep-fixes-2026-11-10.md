# 硬盘休眠修复记录（已纳入 v1.0.2）

基于 v1.0.1 / `577855b`，修复 2026-11-10 两份 NAS 现场文档与项目对照中发现的问题。
本轮修复始于 1.0.1，目前已纳入 1.0.2 发布。请下载 1.0.2 安装包并核对随附 SHA256。本次未在 NAS 上执行。
原控制台的 HTML、CSS、布局与导航保持不变。

## 已修改

1. 删除后端和风扇脚本中的 drivetemp 温度读取及主动加载，消除“先读温度，再查休眠”的路径。
2. 使用共享 `firmware/s2_disk.py` 采集温度与 SMART 兜底：直连 ATA 显式 `-d ata -n standby,3,5`，
   NVMe 显式 `-d nvme`。USB 桥接或无法识别的类型不会自动探测；未知电源状态、命令失败和空结果不会被当成健康数据。
3. 风扇每轮到采样周期时替换温度快照，standby 和 unknown 不再保留旧温度；网页也不展示未知/休眠盘的实时温度，
   风扇缓存超过 90 秒不再用于磁盘温度。
4. 不能安全取温的盘采用至少 30% 风量；如已启用风扇保护，连续异常达到设置次数后全速。
   已确认 standby 的盘不会因此触发保护。未知类型的 USB 盘可能持续触发保守风量，这是当前兼容性边界。
5. 风扇服务改为 `After=local-fs.target`，取消与 `multi-user.target` 的启动环路。
6. 安装、升级、自愈共用禁用迁移：去掉旧 modules-load 文件中的 drivetemp 行、保留其他模块和首份备份，
   写入独立 `s2-no-drivetemp.conf` 黑名单，尝试卸载当前模块。已有用户黑名单不删除。
   模块卸载失败会明确记录，健康诊断也会显示模块仍在运行，需重启后复查。
7. `install_all.sh` 同步部署磁盘采集 helper 和周计划 helper，避免自愈使用不完整的新组件。
8. 历史记录默认暂停；管理员在现有“历史数据保留”卡片中开启。升级前没有显式保存过该开关的旧安装也暂停，
   已有历史数据不删除。关闭时采样线程不访问数据库；通知开启但没有新事件时不重复写入游标。

禁用 drivetemp 后，其他依赖它的应用可能不再显示硬盘 hwmon 温度；本应用改用受保护的 SMART 读取。
这修复的是已知误唤醒路径，不承诺业务读写、访问日志、账号操作、告警事件或其他系统服务不再产生磁盘 I/O。

## 将运维数据放在 SSD / eMMC

这是可选配置；历史记录保持关闭即可停止其周期写入。
需要保留历史时，可以通过 `S2_OPERATIONS_DIR` 指定应用用户可读写的独立目录。

1. 停止应用，确认原实际运维目录（默认应用 var 下的 `operations`）及目标 SSD/eMMC 卷。
2. 将整个运维目录复制到目标位置，保留访问权限。该目录还包含密钥、通知配置、审计和版本，
   不要只复制 samples 或指向空目录，否则这些配置会恢复为空。登录记忆单独保存在应用 var 下的 `auth-sessions.json`。
3. 在应用 etc 下的 `settings.conf` 增加一行，例如：

   ```sh
   S2_OPERATIONS_DIR='/实际SSD卷/s2-operations'
   ```

4. 启动应用，核对配置和历史数据后再开启记录。应用中心改端口或口令时会保留这行路径。

没有自动移动数据库，也没有改动设备现有文件。本地测试仅验证变量传递、配置保留和数据开关。
