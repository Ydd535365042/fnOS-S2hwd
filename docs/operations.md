# 1.0.1 运维功能

2026-11-10 更新的 v1.0.1 已加入[硬盘休眠修复](disk-sleep-fixes-2026-11-10.md)，包含下文的历史记录开关和新取温策略。版本号未递增，请使用本次更新的附件及其 SHA256。

原控制台的导航、卡片位置与
`style.css` 保持不变。新增功能使用独立页面，并复用原来的字体、主题和卡片样式。

## 打开页面

安装 1.0.1 后，在当前控制台地址后加 `/manage.html`，例如
`http://设备地址:18899/manage.html`。先在同一标签页登录，再打开此地址。
原页面没有增加导航入口；运维页提供“返回控制台”。

只输入应用设置中的访问口令即可登录，不使用账号、角色或账号管理。
登录记忆无固定有效期，刷新、新开标签页、关闭浏览器及重启应用后继续有效。
主动退出、修改访问口令或清除本站浏览器数据后需重新登录。
浏览器保存随机会话标识，服务端仅保存其哈希，不保存浏览器中的原始口令。

## 功能与操作入口

| 序号 | 功能 | 使用方式 |
| --- | --- | --- |
| 1 | 配置备份与恢复 | “备份与版本”创建或下载 JSON，导入后预览差异，再确认恢复。恢复前自动备份；预览后配置若发生变化，会拒绝旧确认。 |
| 2 | 历史监控 | “历史监控”查询 CPU、内存、温度、风扇及网络趋势，下载当前查询结果 CSV，设置保留天数。 |
| 3 | 外部告警 | “告警推送”配置 Webhook 或 SMTP 邮件，查看投递记录。仅配置启用后的新事件进入队列，失败最多尝试 4 次。 |
| 4 | 操作审计 | “操作审计”查看操作身份、来源、动作和结果，按身份、动作筛选并导出 CSV。 |
| 5 | 周计划 | “计划与维护”设置开关机时间、星期和跳过日期，查看设备时区与下一次执行时间。 |
| 6 | 健康报告 | “设备健康”下载 JSON 报告，包含硬件、传感器、活动告警、诊断与磁盘变化。 |
| 7 | 故障诊断 | “设备健康”检查温度传感器、RTC、服务与配置；只允许重启本次检查中失败的指定硬件服务。 |
| 8 | 风扇保护 | “风扇保护”配置 CPU/磁盘超温阈值与异常采样次数，超温或 CPU 传感器失效时全速保护。 |
| 9 | 配置版本 | “备份与版本”查看手动及自动版本、差异，按预览确认回退。 |
| 10 | 脚本保护 | 原脚本入口先展示内容、SHA256 和相对上次批准版本的差异；“脚本任务”查看日志、状态或取消运行。 |
| 11 | 维护模式 | “计划与维护”开启限时维护，自动跳过维护期内计划，抑制预期服务告警推送，到期自动恢复。 |
| 12 | 自动化密钥 | “访问密钥”签发指定权限、1–365 天有效期的密钥，仅创建时显示完整值，可立即撤销。 |
| 13 | 多设备 | “多设备”登记控制台地址及目标设备只读密钥，聚合状态与告警，并打开目标控制台。 |
| 14 | SMART 趋势 | “磁盘趋势”按稳定磁盘标识显示历史 SMART 数值及增量；休眠盘跳过采样。 |

## 默认值与数据

- 历史记录默认关闭，升级时未明确保存过开关的旧数据也保持暂停，已有记录不删除。管理员在“历史数据保留”中开启后，每轮约 30 秒采样；SMART 每 10 分钟采样。
- 默认保留 30 天监控数据，可设置 1–365 天。趋势查询使用时间分桶限制响应量，CSV 对应查询结果。
- 最多保留 200 个配置版本、10,000 条审计、1,000 条投递记录；审计单次查询最近 500 条匹配记录。
- 数据保存在应用 `var/operations/operations.sqlite3`；Linux 下文件权限为 `0600`，新建数据目录为 `0700`。
  可通过 `S2_OPERATIONS_DIR` 指定 SSD/eMMC 上的独立目录，迁移方法见硬盘休眠修复说明。
- 配置备份仅包含风扇、灯光、蜂鸣、计划和保护设置，不包含访问口令、API 密钥、通知凭据或监控历史。
  临时维护期限不会被旧备份重新启用。
- 通知与多设备连接凭据保存在服务端私有数据库中，接口不返回完整凭据。
  更换 Webhook 地址或 SMTP 主机/账号时不会沿用旧凭据；更换设备地址必须重新提供密钥。
- SMTP 使用 STARTTLS。Webhook 使用 JSON POST，可配置 Bearer 密钥；不跟随重定向。
  多设备仅访问显式登记地址，最多 20 台，最多 4 个并发连接，结果缓存 15 秒。

## 权限与自动化调用

通过访问口令登录后可以使用控制台的全部功能。未设置口令时，远程访问只读，设备本机可控制硬件。
独立 API 密钥仍可限制自动化访问权限，这不是账号或角色系统。

API 密钥可单独选择 `read`、`control`、`scripts`、`admin`；每个权限独立，
选择 `admin` 不会自动赋予其他权限。自动化请求使用 `Authorization: Bearer <密钥>`。
写请求同时使用 `Content-Type: application/json` 和 `X-S2-Request: 1`。
示例只读端点：`GET /api/ops/overview`、`GET /api/ops/history?hours=24`。

## 硬件与执行边界

- 周计划需要新版 `/usr/local/sbin/s2_schedule.py` 与关机服务；缺少组件时高级规则会明确拒绝。
  升级回调沿用既有流程部署固件，保留已有配置。RTC 唤醒仍依赖主板支持与持续供电。
- 风扇保护由设备上的 `fan-control.sh` 执行，关闭浏览器不会停止保护。默认 CPU 80°C、
  磁盘 55°C，连续 3 次异常触发；低于阈值 3°C 且连续 2 次正常后解除。
  CPU 温度无效视为传感器故障；已确认休眠的磁盘不触发传感器故障保护。
  硬盘温度无法安全读取时采用至少 30% 风量，启用保护后连续达到异常次数会全速；不沿用过期温度。
- 维护模式最多 24 小时，保留风扇保护和温度/磁盘告警推送，所有告警仍可查看。
- 脚本超时范围 10–3600 秒，默认 600 秒。同名脚本不能重复运行，最多 32 个活动任务。
  执行审查通过的内容快照，摘要变化时拒绝执行。日志达到约 16 MiB 时终止任务，检查间隔可能带来少量超出。
  超时退出码为 124，日志上限为 125，取消为 130。取消与子进程组终止依赖 Linux/POSIX。
- 失败恢复会回滚配置文件并尝试重新应用服务；服务本身失败时仍需查看诊断，文件回滚不代表物理硬件已经恢复。

## 验证

本地检查使用临时目录、模拟硬件和模拟外部传输，不操作真实 NAS，也不发送真实通知。

- `tests/test_operations.py`：29 项通过，覆盖恢复冲突、API 密钥权限隔离、旧账号接口禁用、密钥、历史数据、
  告警去重重试、凭据隔离、周计划、风扇保护、配置回滚、脚本超时和日志限制。
- `tests/test_security.py`：19 项通过，1 项 Linux 文件权限检查因 Windows 环境跳过。
- `tests/browser_security.mjs`：27 项真实 Chrome 交互检查。
- `tests/browser_operations.mjs`：74 项真实 Chrome 交互检查，含历史记录开关、仅口令登录及功能流程和 1440/390/360 像素宽度。
- `tests/test_disk_sleep.py`：15 项休眠修复回归检查，覆盖取温边界、安装迁移、风扇循环、无变化不写盘和独立存储路径保留。
- 固件保护函数、计划 apply 函数通过 shell 执行测试；服务、RTC 和硬件调用均替换为测试函数。

尚未验证真实 NAS 安装、RTC 唤醒/关机、物理风扇转速、Linux 进程组取消，以及真实 SMTP/Webhook 投递。
浏览器中的脚本执行使用受控测试结果，真实监督进程另用无害 Python 子进程验证退出、超时和日志限制。
