# 原生硬件与 DTB

入口：**控制 → 已安装模块**。自定义脚本仍在控制页脚本库中执行。控制台布局和访问口令登录方式保持原样。

## 原生控制

应用识别 S2 的标准 PWM 风扇、LED 和温度节点，在驱动可用时接管温控；驱动尚未就绪时保留已有控制器。CPU 温度失效或超温时全速保护；磁盘温度未知时采用保守风量，不把历史温度当成当前温度，也不主动加载 drivetemp。

运行“00-硬件自检.sh”查看 DTB、原生控制器和电源灯美化诊断；执行前先展示操作说明和可展开的脚本内容。

## 升级设备树

1. 确认设备是适配的 WITXIAOHUI S2，在脚本库选择“20-升级S2设备树.sh”并点击运行。
2. 查看脚本内容、摘要与启动分区影响，确认后才执行。安装或升级应用本身不会自动刷写 DTB。
3. 程序先核对板型、DTB 摘要和启动配置，再备份现有文件并更新两个适配 DTB 及 `fnEnv.txt` 中的设备树选择。
4. 查看任务结果。成功后任务输出提示待重启，由你安排重启使新设备树生效，程序不会自动重启。

DTB 来自提供的 `S2自愈最小包-1.1.2.run`，大小 74,587 字节，SHA256：

```text
6dc95aac914dfe5618f09027d31190ae0b84a7efdcc797fa0fa39ecfbbeeb509
```

备份保存在设备的 `/var/backups/fnos-s2-dtb-*`。使用“50-回滚上次DTB升级.sh”回滚本应用生成的有效备份；没有有效备份时拒绝执行。回滚同样需要先审查，完成后安排重启。独立安装的匹配守护器会被识别复用；存在冲突或无法确认的启动文件守护器时拒绝修改并给出原因，避免多个程序反复覆盖启动文件。

## 电源灯美化

确认原生控制可用后，在控制页脚本库选择“30-安装电源灯美化.sh”，审查后执行。效果参考 `S2电源灯美化包-1.1.0.run`：启动等待阶段闪烁、关机阶段显示灯光，并协调蜂鸣和原生控制器，避免重复提示或争用。需要恢复常规灯光时选择“40-停用电源灯美化.sh”。

该效果默认不开启，安装应用不会顺带安装。美化等待有时间上限，不会无限等待网页服务。

## 升级和卸载

升级仅归档内容与旧出厂版本完全一致的旧脚本，自定义脚本保留。卸载会处理本应用部署的控制服务，保留共享脚本、外置运维数据与 DTB 备份；设备树和启动保护不随应用卸载被盲目撤销，需要回滚时先使用对应入口。

本次完成了模拟硬件、服务失败恢复和浏览器操作验证。真实 NAS 的刷写、重启、风扇、灯光、RTC 与硬盘自然休眠仍需实机验证。
