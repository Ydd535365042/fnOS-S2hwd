# 告警通知

告警记录继续显示在控制台右上角铃铛中。点击“邮件 / 推送设置”进入独立通知页面；这里保留邮件和 Webhook 配置、测试通知和投递结果。

## 邮件

1. 推送方式选“邮件”，填写 SMTP 服务器、加密方式、端口、邮箱账号、授权码、发件地址和收件地址。
2. 加密方式选 SSL 时端口通常是 465，选 STARTTLS 时通常是 587；切换加密方式会自动带出对应端口。
3. 点“发送测试通知”。测试使用当前填写的内容，不会保存；失败时页面会说明原因，例如授权码错误、端口与加密方式不匹配、发件地址被拒。
4. 收到测试邮件后，打开“启用告警推送”并点“保存推送设置”。

QQ、163、126 等邮箱需要先在网页版邮箱设置里开启 SMTP 服务并生成授权码，这里填授权码而不是登录密码；发件地址一般要与邮箱账号一致。

| 邮箱 | SMTP 服务器 | 加密方式 / 端口 |
| --- | --- | --- |
| QQ 邮箱 | smtp.qq.com | SSL / 465 |
| 163 邮箱 | smtp.163.com | SSL / 465 |
| Gmail | smtp.gmail.com | SSL / 465 或 STARTTLS / 587 |
| Outlook | smtp.office365.com | STARTTLS / 587 |

## Webhook

Webhook 使用 JSON POST，可选 Bearer 凭据。远端地址会做协议、主机和实际连接地址检查，拒绝回环、链路本地和保留网络地址。

## 其他

更换目标地址、SMTP 服务器或邮箱账号时需要重新填写对应凭据；服务端不会把完整凭据返回到页面。

通知配置继续使用应用原有的私有数据目录，升级不会删除已保存的邮件设置；旧版本保存的 587 端口配置继续按 STARTTLS 发送。通知后台每 5 秒检查一次新告警，只推送启用之后产生的告警，每个事件最多投递 4 次；失败原因会显示在投递记录中。

控制台的普通告警记录、邮件设置和 Webhook 设置可以单独使用。禁用外部通知不会清空本机告警记录。
